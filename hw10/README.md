# ДЗ10 — Захищений REST API

Самостійна версія API контактів з автентифікацією, JWT `access_token`, підтвердженням email, Redis-лімітом `/me`, CORS і Cloudinary. Кожен користувач бачить та змінює лише власні контакти. Паролі хешуються Argon2.

```powershell
Copy-Item .env.example .env
docker compose up --build -d
```

Swagger: http://localhost:8010/docs. Локальна пошта Mailpit: http://localhost:8110. PostgreSQL і Redis доступні лише всередині Compose-мережі; міграції виконуються автоматично.

1. У Swagger виконайте `POST /auth/signup` з `username`, `email`, `password` (мінімум 8 символів). Статус успіху 201; повторний email або username — 409.
2. Відкрийте лист у Mailpit і перейдіть за посиланням підтвердження. Повторне надсилання: `POST /auth/request-verification`.
3. Натисніть **Authorize** та введіть username (або email) і пароль. `/auth/login` приймає form-data у тілі й повертає токен; помилкові облікові дані дають 401. Непідтверджена пошта — 403.
4. Використовуйте `/contacts` для CRUD, `q` для пошуку та `/contacts/birthdays` для найближчих семи днів. Чужі контакти повертають 404.
5. `/me` дозволяє 10 запитів за 60 секунд для одного користувача; наступні повертають 429. Ліміт задається `ME_LIMIT`.
6. Для `PATCH /me/avatar` заповніть у `.env` `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`, перезапустіть app і завантажте JPEG/PNG/WebP до 2 MiB. У ДЗ10 будь-який автентифікований користувач може змінити власний аватар.

`.env.example` містить лише навчальні значення. Згенеруйте JWT-секрет: `python -c "import secrets; print(secrets.token_urlsafe(48))"`. Перелік дозволених фронтенд-адрес задається JSON-масивом `CORS_ORIGINS`. Для зовнішньої пошти налаштуйте `SMTP_*`, `MAIL_FROM`, `PUBLIC_URL`; за замовчуванням листи залишаються локально в Mailpit.

POST створення контактів і користувачів повертають 201. Вхід та повторне надсилання листа — операції без створення нового ресурсу, статус 200. PUT повністю замінює контакт; DELETE повертає 204. Семиденний інтервал включає сьогодні та шість наступних днів, враховує перехід року; 29 лютого у невисокосний рік обробляється як 28 лютого.

Ця версія також використовує Redis-кеш авторизації. При недоступності Redis захищені маршрути повертають 503. Ролі та зміна пароля розвинені у фінальній роботі `hw12`.
